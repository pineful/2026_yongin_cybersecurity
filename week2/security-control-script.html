Slide 6 / 46 1교시 · Evaluation Metrics · 관제 정확도 평가
보안관제 정확도 4분면: 정탐(TP)·미탐(FN)·오탐(FP)·정상(TN)
🎤 표준 강의 멘트 (1~2분 구어체 · 화면 1:1 매칭)

보안관제 요원이 매일 마주하는 4가지 상황, 혼돈 행렬(Confusion Matrix) 기반의 정확도 체계입니다.

1번 '정탐(True Positive)'은 실제 해커가 공격했고 시스템이 정확히 경보를 울려 차단에 성공한 가장 이상적인 상태입니다.

2번 '미탐(False Negative)'은 가장 끔찍한 재앙입니다. 실제 해커가 침투했으나 시스템이 경보를 울리지 못하고 침묵하여 회사가 털리고 있는 상태입니다. 맑은소프트 48시간 지연이 전형적인 미탐입니다.

3번 '오탐(False Positive)'은 정상 직원의 업무 행위인데 규칙이 너무 빡빡해서 해킹이라고 엉뚱한 경보를 울려 관제사를 지치게 만드는 '양치기 소년'입니다. 4번 '정상(True Negative)'은 평화로운 일상입니다. 보안에서는 오탐보다 미탐이 수천 배 더 위험합니다.

서버마다 직접 들어가서 로그를 뒤지는 시대는 끝났습니다. 수백 대 장비에 경량 Agent를 심어 실시간 전송하는 SIEM 구조입니다.

또한 장비마다 제각각인 로그 형식을 공통 스키마로 번역하는 '정규화(Normalization)'를 수행합니다. 어떤 장비는 src_ip, 어떤 장비는 ClientAddress로 표기하는 것을 source.ip로 통합해야 단 한 번의 쿼리로 전체 시스템을 추적할 수 있습니다.

Slide 8 / 46 1교시 · OS Log Structure · 로그 비교
윈도우 vs 리눅스 로그 구조: Event ID와 /var/log
🎤 표준 강의 멘트 (1~2분 구어체 · 화면 1:1 매칭)

침해 사고 분석 시 가장 먼저 확인해야 할 양대 운영체제의 핵심 로그 저장소입니다.

좌측의 '윈도우 이벤트 로그(Security.evtx)'는 구조화된 XML 바이너리로 기록되며 고유한 Event ID를 가집니다. Event ID 4624는 로그인 성공, 4625는 로그인 실패(무차별 대입 증거), 4672는 관리자 특권 할당, 7045는 신규 서비스 설치로 백도어 탐지에 필수입니다.

네트워크 보안 장비의 핵심 3총사, 방화벽·IDS·IPS의 물리적 배치와 역할 차이입니다.

첫째, '방화벽(Firewall)'은 출입 통제 문지기입니다. IP와 포트 번호(L3/L4)만 보고 통과/차단을 결정하므로, 80/443 웹 포트가 열려 있으면 패킷 속 SQL 인젝션 같은 악성 코드는 그냥 통과시킵니다.

둘째, 'IDS(침입 탐지)'는 복사본을 훔쳐보는 CCTV입니다. 트래픽을 미러링으로 받아 해킹 패턴을 감지하면 경보(Alert)만 울릴 뿐, 패킷을 직접 차단할 권한이 없습니다.

셋째, 'IPS(침입 방지)'는 통신선 한가운데(In-line)에 직접 칼을 빼 들고 선 무장 경호원입니다. 악성 패킷 감지 즉시 패킷을 파기(Drop)하고 연결을 강제 종료합니다. 다만 장비 장애 시 네트워크 전체가 마비될 수 있는 부담이 있습니다.

이에 맞서는 방어자의 대책은 두 가지입니다. 첫째는 한 번 쓰면 root 권한으로도 수정이나 삭제가 불가능한 'WORM(Write Once, Read Many) 스토리지'에 로그를 보관하는 것입니다. 둘째는 로그가 찍히자마자 0.1초 만에 격리된 원격 SIEM으로 실시간 복사 전송하여 로컬 조작을 원천 차단하는 것입니다.
