SOC Philosophy · 관제의 본질

보안관제(SOC)의 본질: "화면 보기"가 아니라 "맥락 읽기"

수천만 건의 정상 로그 속에서 숨어든 1건의 악성 행위를 찾아내어 피해를 막는 기업 보안의 최전선

❌ 흔한 오해: 24시간 단순 화면 감시?

모니터에 빨간 불이 들어오면 서버를 재부팅하는 단순 직무가 아닙니다.

  • 수억 건의 빅데이터: 사람이 눈으로 다 읽을 수 없는 거대한 로그 규모
  • 인터넷 노이즈: 단순 방화벽 차단 로그의 99.9%는 무차별 스캐닝에 불과함
  • 핵심 과제: 노이즈 속에 숨어든 고도화 타깃 공격(APT) 1건을 식별해야 함

✅ 보안관제의 진짜 일: 맥락(Context) 분석

흩어진 로그들을 시간 순서대로 꿰어 공격 시나리오 전체를 재구성합니다.

  • 상관 분석: 로그인 실패 5회 직후 외부 IP에서 관리자 토큰 획득 감지
  • 골든타임 사수: 공격자가 핵심 DB로 횡적이동하기 전 방화벽 즉각 차단
  • 증거 보존: 공격자 침입 경로 및 피해 범위를 명확한 침해 보고서로 작성
수억 건의 빅데이터에서 1건의 진짜 침해 사고(Critical Incident)를 적발하는 SOC 정제 파이프라인

Evaluation Metrics · 관제 정확도 평가

보안관제 정확도 4분면: 정탐(TP)·미탐(FN)·오탐(FP)·정상(TN)

관제 요원이 매일 마주하는 4가지 상황: 왜 보안에서는 오탐보다 미탐이 수천 배 더 위험한가?

1. 정탐 (TP)

이상적 차단 성공

실제 해커의 공격을 정확히 감지해 즉시 차단한 완벽한 상태.

2. 미탐 (FN)

🚨 최악의 재앙

해커가 침투했으나 경보가 울리지 않아 침해를 인지조차 못함.

3. 오탐 (FP)

경보 피로 유발

정상 업무 트래픽을 공격으로 착각해 불필요하게 사이렌 울림.

4. 정상 (TN)

평온한 일상

정상 행위를 정상으로 올바르게 판정하여 통과시킨 상태.

보안관제 정확도 평가 2x2 혼동 행렬 (Confusion Matrix)

SIEM Architecture · 수집 구조

SIEM의 등장과 다중 에이전트(Agent) 수집 체계

서버마다 직접 들어가서 로그를 보는 방식의 종말: 수백 대의 장비에 Agent를 심어 실시간 전송
💡 용어 돋보기 SIEM (Security Information & Event Management) = 통합 보안관제 플랫폼 · 기업 내 모든 장비의 로그를 중앙 수집·정규화·상관분석하는 관제 사령탑

📦 각 서버별 Agent 설치의 필수성

중앙 SIEM이 원격 로그를 알아서 가져올 수 없습니다. 각 서버마다 Logstash, Wazuh Agent 등 경량 수집기를 설치해 발생 즉시 암호화 푸시(Push)해야 합니다.

방화벽 vs IDS vs IPS: 역할과 배치의 결정적 차이

출입을 통제하는 문지기, 침입을 지켜보는 CCTV, 그리고 칼을 빼 드는 무장 경호원

방화벽 (Firewall) = 문지기

L3/L4 IP·포트 기반 출입 통제.

  • IP 주소와 포트 번호만 보고 출입 허용/차단 결정
  • 한계: 80 웹 포트가 열려 있으면 웹 공격 패킷은 통과시킴

IDS (침입 탐지) = CCTV

복제 패킷 미러링 수동 감시.

  • 미러링(SPAN/TAP) 방식으로 원본 패킷 흐름에 지연 없음
  • 한계: 탐지하여 경보만 울릴 뿐 실시간 차단은 불가능

IPS (침입 방지) = 경호원

인라인(In-line) 배치 실시간 차단.

  • 트래픽 길목 한가운데 서서 악성 패킷 발견 즉시 세션 드롭
  • 주의점: 오탐 시 정상 사용자 통신까지 강제 차단됨

시그니처(Signature) 탐지 vs 이상 행위(Anomaly) 탐지

수배 전단지 대조 방식의 확실함과, 처음 보는 거동 수상자를 잡아내는 통계적 직관

📜 시그니처 기반 탐지 (Pattern Matching)

이미 알려진 악성코드 및 공격 문자열(수배 전단)과 1:1 비교합니다.

  • 장점: 오탐률이 극히 낮고 명확한 근거(CVE 번호)가 제시됨
  • 단점: 한 번도 공개된 적 없는 신종 제로데이(Zero-Day) 공격은 탐지 불가
  • 대표 도구: Snort, Suricata, ClamAV 등 시그니처 매칭 엔진

📈 이상 행위 기반 탐지 (Anomaly Detection)

정상 기준선(Baseline)을 학습하고 이를 크게 벗어나는 패턴을 포착합니다.

  • 장점: 수배 전단이 없는 신종 침해 기법도 통계적 이상으로 탐지 가능
  • 단점: 월말 정산 등 정상적인 대용량 트래픽에 대한 오탐(False Positive) 빈발
  • 대표 도구: Zeek, SIEM 행동 분석(UEBA), 머신러닝 이상 탐지기
시그니처 탐지(Snort) vs 이상 행위 탐지(Zeek) 상호보완 관제 모델
알려진 위협 즉각 차단 + 신종 위협 이상 징후 추적
시그니처: "수배범 사진과 대조"
패킷 내 `UNION SELECT` 문자열 일치 즉시 경보 (정확도 100%, 변종 우회 취약)
이상 행위: "평소와 다른 수상한 거동 감시"
야간 시간대 단시간 수백 개 포트 접속 시도 통계 포착 (미지의 제로데이 탐지)

Snort & Suricata 룰 문법: 패킷 검사 규칙의 해부

헤더 영역과 옵션 영역으로 나뉘는 글로벌 표준 시그니처 규칙 구조를 파헤칩니다.
Snort Rule Example
alert tcp $EXTERNAL_NET any -> $HTTP_SERVERS 80 (
  msg:"WEB-ATTACK SQL Injection Attempt - UNION SELECT";
  content:"UNION"; nocase;
  content:"SELECT"; nocase;
  sid:1000001; rev:1;
)

1. Action & Protocol

alert tcp : 조건을 만족하면 실시간 경보를 생성하고 패킷을 파일에 기록합니다.

2. Header Scope

외부망 모든 포트에서 사내 웹 서버 80번 포트로 향하는 인바운드 트래픽 한정.

3. Content Match

페이로드 내 UNION과 SELECT 단어가 대소문자 무관 포함될 때 정밀 탐지.

[기초 보충] 리눅스 배포판 양대 산맥: 데비안(Ubuntu) vs RHEL(Rocky)

보안관제에서 서버 로그를 찾을 때 가장 헷갈리는 패키지 매니저와 설정 파일 위치의 결정적 차이

🟠 데비안 계열 (Ubuntu / Debian / Kali)

개발 친화적이며 클라우드와 인공지능 서버 환경의 사실상 표준.

  • 패키지 매니저: apt / dpkg (.deb 패키지)
  • 인증 로그 위치: /var/log/auth.log (SSH 로그인 감시)
  • 방화벽 도구: ufw (Uncomplicated Firewall) 및 iptables

🔴 RHEL 계열 (Red Hat / Rocky / CentOS)

금융권 및 엔터프라이즈 사내 인프라의 절대 강자.

  • 패키지 매니저: dnf / yum / rpm (.rpm 패키지)

🔍 진실: 정확히 같은 순간(0초 차이)의 연계 공격!

KST는 UTC 기준시보다 정확히 9시간 빠릅니다 (UTC + 9 = KST).

  • 05:15:00 UTC에 9시간을 더하면 정확히 14:15:00 KST 일치
  • 9시간 간격의 지연 공격이 아니라 실시간으로 일어난 단일 침해였음
  • 실무 교훈: SIEM 통합 로그 분석 시 전 서버 표준시(UTC) 통일 필수
NTP Architecture · 동기화 계층

NTP의 원리와 계층 구조: 원자시계부터 내 서버까지 (Stratum)

네트워크 지연 시간을 자동으로 감산하여 전 세계 컴퓨터의 시계를 1ms 오차 내로 맞추는 프로토콜 (123번 UDP)

Stratum 0 (최상위 기준)

초정밀 물리적 시간 하드웨어.

  • 세슘 원자시계 및 GPS 위성 시계 신호
  • 네트워크에 직접 물리지 않고 Stratum 1에 직결

Stratum 1 (국가 표준)

원자시계 직결 1차 표준 타임 서버.

  • 한국표준과학연구원(KRISS) 등 국가기관 운영
  • 일반 서버가 직접 물리면 과부하가 걸리므로 제한

Stratum 2 & 내 서버

기업 사내 표준 및 실무 노드.

  • 사내 NTP 마스터 서버가 Stratum 2 동기화 수령
  • 사내 수천 대 서버(Stratum 3)로 정밀 시간 전파

TERM 01 시간 동기화

NTP

네트워크를 통해 서버 간 시계를 밀리초 단위로 일치시키는 네트워크 시간 동기화 프로토콜.

TERM 02 신뢰도 계층

Stratum

원자시계(Stratum 0)부터 시작하여 시간 소스의 계층적 신뢰도를 나타내는 0~15단계 등급.

TERM 03 시간 오차

Time Drift

하드웨어 클록 오차로 인해 시간이 흐를수록 서버 시계가 수 초~수 분씩 어긋나는 물리적 현상.

TERM 04 시간대 함정

UTC vs KST

국제 표준시(UTC)와 한국 표준시(UTC+9) 표기 차이로 인해 발생하는 9시간 분석 착오 위험.

TERM 05 증거 인멸

Timestomping

해커가 침투 흔적을 지우기 위해 파일의 생성·수정 타임스탬프를 조작하는 안티 포렌식 기법.
