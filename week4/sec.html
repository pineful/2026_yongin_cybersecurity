table: 보고 싶은 열만 남긴다

나열·변환
문법과 성질

table <필드1> <필드2> … <필드n>

  • 필드명과 결합해 검색 결과를 테이블 형태로 보여준다
  • 필드명을 잘못 적으면 해당 필드에 공란이 보인다
  • 필드명은 대소문자를 구분한다
  • 여러 필드는 쉼표(,) 또는 띄어쓰기로 구분한다

다른 필드에는 값이 보이는데 특정 필드가 공백이면 필드명 입력 오류를 의심한다

dedup: 중복을 지우면 다른 값도 사라진다

주의

중복을 제거하면 다른 필드의 값은 중복이 아닌데도 중복된 결과를 제거하면서 사라진다.

문법과 쓰임

dedup <필드명1>, <필드명2>

  • 중복 제거는 지정한 필드를 기준으로 실행한다
  • 두 개 이상의 필드는 쉼표(,)로 구분한다
  • 상세 분석이 아니라 해당 필드에 존재하는 값을 확인하는 정도로 사용한다
index=bookstore sourcetype=access_combined_wcookie status=404
| dedup host

전 — status=404 결과

hostclientip
www110.2.1.12
www210.2.1.47
www110.2.1.88

후 — host 중복 제거

hostclientip
www110.2.1.12
www210.2.1.47

10.2.1.88의 행이 함께 사라졌다

fields: 계산 전에 줄이면 빨라진다

성능
포함시킨다 — fields +

fields + <필드명>

검색 결과에서 특정 필드를 포함시킨다.

제외한다 — fields -

fields - <필드명>

검색 결과에서 특정 필드를 제거한다.

왜 성능이 오르나

+는 기본값이므로 반드시 명시할 필요는 없다. 필드를 추출하기 전에 동작하므로, 원하는 필드만 선택하면 전체 검색 성능을 높일 수 있다.

필드가 많을수록 뒤 단계가 처리할 양이 늘어난다 — 앞에서 줄이는 편이 싸다.

cidrmatch: IP가 대역 안인지 참·거짓으로 본다

관제의 기본 분류
동작 방식

cidrmatch("X", Y)

  • IP주소 Y가 네트워크 범위 X에 존재하는지 확인한다
  • 반환 값은 참 또는 거짓이며 두 개의 인자를 사용한다

if: 조건에 따라 값을 고른다

local / external
동작 방식

if(X, Y, Z)

X가 참이면 Y를 실행하고, X가 거짓이면 Z를 실행한다.

조건 판정 결과로 두 값을 고르는 삼항 판정이다

| makeresults
| eval ip1="10.10.0.100", ip2="100.10.0.100"
| eval network1=if(cidrmatch("10.10.0.0/24", ip1),"local", "external"),
network2=if(cidrmatch("10.10.0.0/24", ip2),"local", "external")
| table ip1, network1, ip2, network2

IP 필드 값이 10.10.0.100이라면 10.10.0.0/24 네트워크에 포함되므로 network1 필드에 local 문자열이 저장되고, 100.10.0.100이라면 network2 필드에 external이 할당된다.

like는 부분 일치, match는 정확 일치

% vs 정규식
like(X, "Y")
  • X 필드에서 일부 문자열인 Y를 검색한다
  • X에서 Y를 찾을 수 있으면 참을 반환한다
  • 와일드카드 문자열은 %
… | where like(field, "add%")
* field 변수가 addr로 시작하는지 검사
match(X, "Y")
  • like가 일부라도 맞는 값을 찾는다면 match는 정확한 일치 여부를 비교한다
  • 문자열 비교에 대소문자는 구분하지 않는다
  • $는 종결자 — 앞의 문자로 단어가 끝난다는 의미, |는 다중 선택
match(filename, "malicious.exe")
match(filename, "(.jpg|.gif|.png)$")
* 파일 확장자가 jpg, gif, png 여부를 검사

where NOT match: 허용되지 않은 메서드를 찾는다

네 줄 해부

| where NOT match(method, "(GET|POST|-)")
| stats count(src) as src_count by method
| sort -src_count

② 집계검사된 메소드들 별로 송신지 주소 개수를 세서 결과 반환
③ 저장개수 count(src)를 src_count에 저장
④ 정렬저장된 src_count 값을 기준으로 내림차순 정렬

mvindex: 조각 중 하나를 고른다

0과 -1
동작 방식

mvindex(X, Y, Z)

  • 필드 X에 있는 Y번째 값을 반환한다 (Z 생략 가능)
  • Y는 인덱스 번호 — 0은 첫 번째 값, -1은 뒤에서 시작, -2는 끝에서 두 번째
  • Z를 지정하면 Y부터 Z까지의 값을 반환한다
원본 4-4~5 p30 [정리] 앞에서는 0부터, 뒤에서는 -1부터 센다
04~05

substr: 문자열 일부를 자른다

시작과 개수

substr(X, Y, Z)

세 번째 인자 Z가 없다면 필드 X의 Y부터 시작해서 문자열 끝까지 반환하고, Z가 주어지면 Y부터 Z개의 문자열을 반환한다.

*| eval passwd_str="lightdm:x:107:117:Light Display Manager:/var/lib/lightdm:/bin/false"
| eval uid=mvindex(split(passwd_str,":"),0)
| eval subuid1=substr(uid,2)
| eval subuid2=substr(uid,2,4)
| table uid, subuid1, subuid2
원본 4-4~5 p31~p33 [정리] Y는 시작 자리, Z는 개수다 — 셋째 인자가 없으면 끝까지

04~05

timechart: 시간축으로 집계한다

span=12h
문법

timechart span=[시간범위] 통계함수 by [필드명]

  • 시간에 따른 통계 테이블을 생성한다
  • 시간 필드가 X축, 실제 데이터가 Y축에 표시된다
  • 시간에 따른 통계의 추세를 표시할 때 많이 사용한다
  • count — 전체 개수를 12시간 단위로 구해 보여준다 / span — 시간 계산 단위 설정
index=bookstore sourcetype="access_combined_wcookie"
| timechart span=12h count(clientip) as "Access Count"
0h12h24h36h48h
원본 4-4~5 p35 [정리] 언제 몰렸는지가 궁금하면 timechart다
04~05

chart: 축을 내가 정한다

over by
문법

chart [통계함수] over X축 by [기준필드]

  • timechart와 유사한 방식으로 동작한다
  • timechart는 span 옵션으로 시간 단위를 지정할 수 있지만, chart 명령어는 해당 옵션을 사용할 수 없다
index=bookstore sourcetype="access_combined_wcookie"
| chart dc(clientip) as "Unique Count" over date_wday
월화수목금

over date_wday — 요일이 X축이 된다

원본 4-4~5 p36 [정리] 축을 무엇으로 할지가 먼저다 — over 뒤에 쓴다

Task 4 VIP 표시 룩업을 사용하여 VIP 고객 상품 구입 정보 표시
